01 — FoundationBrand & Interface System

Confident. Playful.
Precise.

The studio makes premium work for small teams. The system has to feel expensive without feeling cold — so it pairs editorial restraint with pop-art nerve.

Confident

One idea per screen. Huge type, short lines, no hedging. If a sentence needs a second clause to survive, it gets cut.

Playful

Colour does the entertaining. Full-bleed bands, sticker outlines, a music button that wears whatever colour the page is wearing.

Precise

Nothing decorative for the sake of it. Every card is a grid cell, every animation is a beat, every colour is a role.

Voice

First person, present tense, declarative. The studio speaks as “I” in headlines and “we” in service copy. Sentence case. Full stops. No exclamation marks — the colour already shouted.

Design that earns its place.

Nothing decorative for the sake of it.

Personality in one line

A studio that treats a website like a physical object: printed, cut out, and stuck down with real ink outlines.

Never

  • Gradients, glows, or soft shadows
  • Grey-on-grey “premium” minimalism
  • Stock photography of laptops
  • More than one loud accent per screen

All four are card and accent fills only — never text, never an action colour. Sage fails 4.5 : 1 on three of five bands, so muted copy is ink at 70% instead.

Rules

  • Lime never fills chrome, navigation, or decoration. It is the primary action and nothing else: as a ring it fails 3 : 1 on Paper, Lavender and Leaf.
  • No two bands of the same colour are ever adjacent.
  • Strokes are pure ink. Muted text is ink at 70% (90% on Cobalt) — never lower, never a flat grey.
  • No gradients. A band is one flat colour, edge to edge.

03 — The chameleon ruleBrand & Interface System

Colour follows
the scroll.

The interface is never a fixed colour. Every band publishes the colour it is wearing, and the fixed chrome — music button, menu button, menu row — reads it and repaints.

01 · Home#F5F5F3INK #00019.2 : 1muted 70%
02 · About#E9C0E9INK #00013.2 : 1muted 70%
03 · Our Works#780016INK #FFF11.6 : 1muted 70%
04 · 3D Scene#2665D6INK #FFF5.4 : 1muted 90%
05 · Work With Us#EBFFC5INK #00019.6 : 1muted 70%

The mechanism

Each band declares data-bg. On entry the deck writes it to two custom properties and every fixed element inherits them:

--chrome-bg : the band colour --chrome-fg : black or white, by luminance .music, .burger { background: var(--chrome-bg); color: var(--chrome-fg); }

The threshold

Ink flips at relative luminance 0.179, the point where black and white give equal contrast. Black above, white below: every band gets whichever ink reads better.

Why 0.179, not 0.45. The old line sent Mustard (L = 0.408) to white ink at 2.3 : 1. At 0.179 it resolves to black at 9.2 : 1, so no band needs a manual override.

Never hardcode

Chrome never names a colour. It asks the band. Adding a sixth band requires no CSS for the chrome at all.

Never invert alone

When a control is “on”, it swaps the pair — fill becomes ink, ink becomes fill. It never introduces a third colour.

Always test both

Every chrome state is reviewed on all five bands before it ships. A control that only works on Paper is not finished.

04 — TypographyBrand & Interface System

Two voices.
Tight tracking.

Space Grotesk speaks; Inter explains. Headlines are set as shapes, not sentences, and tracking goes negative as the size goes up.

Space Grotesk — display

Headlines, section titles, card titles, prices, menu rows. Weight 700 only — the heaviest cut Space Grotesk ships. Negative tracking from −0.02em at 16px to −0.045em at 62pt.

Inter — interface

Body, labels, buttons, footnotes, metadata. Weights 400 and 600. Labels are sentence case at +0.02em; wide-tracked caps at 12px hurt legibility.

Optical notes

Tight tracking only works above 20px. Below that, −0.01em is the floor — anything tighter starts to collide. Cap body lines at 70 characters.

Hierarchy

05 — Layout & rhythmBrand & Interface System

One section.
One screen.

The site is a deck, not a page. Each band is exactly one viewport tall and snaps; there is no in-between state where two sections share the screen.

Deck

A single scroll container with scroll-snap-type: y mandatory and scroll-snap-stop: always. Sections are 100dvh, so mobile chrome can never crop the composition.

Gutters

5vw on every side, every breakpoint. Content is capped at 1200px and centred, so the same composition survives a 13-inch laptop and a 6-inch phone.

Vertical padding

88 / 64 at rest, stepping down to 44 / 18 on very short viewports. The label sits at 4.75rem from the top, the number mirrors it on the right.

Fit guard

If a band's content is taller than its padded height, the inner block scales down — never below 0.7 — Past that, the band grows beyond 100dvh and snapping drops to proximity, so nothing clips at 200% zoom or large text.

06 — Shape & elevationBrand & Interface System

The border is
the elevation.

There are no shadows in this system. A 2px ink outline does all the lifting — it is what makes every surface read as a sticker rather than a pane of glass.

Radius set — four values, no others

SurfaceRadius
Chrome / pills / tags99px
Cards, tiles, works, CTA card32px
Cards and compact rows, ≤900px24px
Buttons, menu rows16px

Outline

--stroke: 2px solid #000, applied on every card, tile, button and pill. On the darkest bands the stroke stays black — the fill provides the contrast, never a white outline.

No exceptions

No blur behind cards, no inner shadow, no glassmorphism. The only blur in the system is the fixed menu frost, and that is a documented state (page 11).

Do
  • Give every new surface the same 2px ink stroke
  • Let colour contrast carry hierarchy inside a card
  • Keep radius proportional to area — bigger surface, bigger curve
Don't
  • Add box-shadow to imply depth
  • Outline a surface with 1px — only dividers inside tables and lists are hairlines
  • Round a button to 32px to match a card

08 — MotionBrand & Interface System

Motion explains
or confirms.

Nothing moves decoratively. Every animation either explains where content came from or confirms that an input landed.

The intro — 3.68s, once per session, skippable

Five clip-path shapes swap every 287.5ms, each rotating 20° as it lands: circle → triangle → hexagon → square → plus. The lockup compresses to an 11px dot, the dot stretches into a full-height line, and the line scales out to flood the viewport in the band's own colour. The overlay is lifted on the same frame the flood completes — because the flood is the section colour, there is no flash and no second curtain. Any key or tap skips it; under reduced motion it becomes a 300ms fade.

Section reveal

The first time a band enters view, its blocks rise 26px and fade in: 0.8s on --out, 75ms stagger. Once per section per page load — returning to a section never replays it.

The hero is excluded from the observer and is cued by the intro's handover, so it rises exactly as the page is revealed.

Deck colour

The page background cross-fades over 500ms while the band scrolls in. Scroll snapping itself is instant — the deck never animates a landing.

Feedback

The music toggle pops its icon 1 → 1.3 → 0.92 → 1 over 440ms on cubic-bezier(.34,1.56,.64,1). The burger uses the same spring over 520ms. Both are confirmations, not decoration.

Three curves

--ease: cubic-bezier(.25,.1,.25,1)
--out: cubic-bezier(.215,.61,.355,1)
--spring: cubic-bezier(.34,1.56,.64,1)

Transform only

Animate transform, opacity, clip-path and colour. Never animate layout — the deck's snap maths needs stable geometry, so the flood scales rather than widens.

Reduced motion

Every reveal, pop and transition is disabled under prefers-reduced-motion. Content is visible from the first frame.

09 — Chrome & navigationBrand & Interface System

Fixed controls
borrow the band.

Three fixed elements sit above the deck: the logo, the music toggle, and the menu. All of them are monochrome, all of them borrow the current band.

Music toggle
♪ ♪

Off = band fill with contrast ink. On = the pair inverted. The glyph is a hand-drawn two-note mark at 2px; a diagonal slash fades out when playing. 42px, dropping to 38 / 34 / 30 on short viewports; the hit area stays 44px.

Menu button
✕

Three rounded strokes, the middle one short — that asymmetry is the “cute”. On open they fold into a cross, the button inverts, and it pops on the spring curve every tap.

Section menu

Mobile only (≤900px). It opens over a 50% paper frost with an 18px backdrop blur — everything behind it reads as blurred out, but the colour still shows through. Rows enter in a 55ms stagger.

Each row is a real anchor, so the deck's own snap and paint logic runs. The row for the current band is filled with that band's colour and its contrast ink; every other row stays black.

Logo

Space Grotesk 700: “amir” at 0.625rem, “STUDIO” at 1.25rem, ™ at 0.625rem, with a 0.625rem tagline — nothing in the lockup drops below 10px. Set in --chrome-fg like the rest of the chrome. A difference blend looks monochrome on Paper but turns orange on Cobalt and cyan on Maroon.

Clearance

Fixed chrome owns a lane. If a band's copy would slide under the music button, that band's top padding is nudged — never the button's position.

Opening and closing: the frost fades over 440ms while rows rise; closing reverses with no stagger, so dismissal is always faster than arrival. Escape closes it and returns focus to the button. While open, the menu owns the arrow keys, keeps focus inside, and the deck behind it is inert.

10 — Tokens & accessBrand & Interface System

The source
of truth.

CSS variables

:root{ /* surfaces */ --paper:#F5F5F3; --white:#ffffff; --ink:#000000; --sage:#676b5f; /* bands */ --lavender:#e9c0e9; --cobalt:#2665d6; --maroon:#780016; --leaf:#ebffc5; /* accents */ --lime:#d2e823; --forest:#254f1a; --mustard:#d6a337; --midnight:#1e2330; /* shape */ --stroke:2px solid #000; --r-pill:99px; --r-card:32px; --r-card-sm:24px; --r-btn:16px; /* motion */ --ease:cubic-bezier(.25,.1,.25,1); --out:cubic-bezier(.215,.61,.355,1); --spring:cubic-bezier(.34,1.56,.64,1); /* live chrome */ --chrome-bg:#f5f5f3; --chrome-fg:#000000; }

Ink resolver

const lin = c => { c = parseInt(c, 16) / 255; return c <= 0.04045 ? c / 12.92 : Math.pow((c + .055) / 1.055, 2.4); }; const L = hex => .2126 * lin(hex.slice(1,3)) + .7152 * lin(hex.slice(3,5)) + .0722 * lin(hex.slice(5,7)); const ink = hex => L(hex) > 0.179 ? '#000000' : '#ffffff';

Band contract

<section data-bg="#2665d6">

Paint reads data-bg, writes --chrome-bg / --chrome-fg, and emits amir:section with the id. Chrome and menu only listen.

Accessibility floor

  • Focus is a 3px ring, offset 4px, in the band's ink on every control. Lime fails 3 : 1 on three of five bands.
  • Every band clears 4.5:1 for body text with its resolved ink.
  • Reduced motion removes every entrance, pop and colour transition, and turns the intro into a fade.
  • Menu is a real nav with aria-expanded, aria-controls and a current-row marker.
  • Hit areas stay ≥ 44px: chrome gets an invisible halo that grows as the visible control shrinks.
  • The music toggle is aria-pressed and never autoplays.

Pre-flight

  • Is every surface stroked at 2px?
  • Is there exactly one lime object on screen?
  • Does the chrome read on all five bands?
  • Does anything clip below 0.7 scale?
  • Do the buttons share a baseline?
  • Does it still work with motion turned off?
If it needs a shadow to work, it isn't finished.
